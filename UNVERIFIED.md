| 14 | How often the rewriter changes a prompt in a way the judge calls worse | **Open: the current prompt misses the harm and benefit bars on realistic prompts.** A paired comparison on 2026-10-19 (175 generated prompts and 150 of the maintainer's own history prompts, 4 rewrites each, 1,300 pairs) found, for the current prompt, 22 worse of 1,299 decided samples (1.7%, 95% upper limit 2.4%, against a limit of 2%) and 85 better, so 3.9 better per worse (against 5). By source: 10 of 699 on the generated prompts and 12 of 600 on the history prompts. 64% of the rewrites were unchanged, 22% equal and 6.4% refused by the guard. The worse samples on the generated prompts are of four kinds: a tentative request hardened into a firm one ("maybe also persist to sessionStorage" became a requirement, 4 of 4 samples), a softener dropped ("a bit"), an instruction or constraint added ("do not touch prod", a prescribed fix), and a non-English prompt translated into English (a German prompt, 3 of 4). The stress suite adds a class that realistic prompts rarely trigger: a reference the developer left open settled by the rewriter ("after that", "dafür", "anywhere" narrowed once a place is named). On the 1.0.0 prompt it was 4.1% of 832 samples (34 worse, in four prompts), and the twins that state the tail explicitly had 0 worse of 32, so long lists themselves are handled. A prompt sentence that keeps such references open (PR #17) cut the stress-suite rate to 2.6% but did not carry over: paired on realistic prompts it gave 27 worse against 22 (one-sided p 0.91 that it has fewer, and 19 against 12 on the history prompts), so it was not adopted and the PR was closed. Fixing the four kinds above is the work still to do before the bars can be met. |

## Not verifiable

- The exact status the API returns when a balance is empty (item 7) stays unobserved by design; the classifier does not depend on it.
- The 2025-11-10 `claude.com` blog post on prompt engineering and the Console prompt tools' own docs were read only through a summarizer, so their quotes in `docs/research-notes.md` are unconfirmed. Neither changes a rule: the platform docs win where they differ.
- Whether CI can run `tsc -p .`. On 2026-10-19 `claude plugin validate --strict .` and `claude plugin test .` were run on a copy without `.claude-plugin/types/` and neither wrote it, so `verify` leaves type errors and `evals/*.ts` unchecked. Run `tsc -p .` locally before a PR (item 11).
- Whether a **tag** ref pins the plugin files as a branch ref does (item 20). No tag exists yet; check `claude plugin list` after the first release.
- The rewriter's three examples have no outer `<examples>` tag, which the best-practices page recommends for several examples. Changing it is a system-prompt edit that needs a before and after eval, so it is a candidate for after 1.0.0.
